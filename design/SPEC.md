## 3. 核心規則（原型：春季）

所有數字集中放在 `data.js` 的常數區，以下為初始值，之後靠模擬測試調整。

### 3.1 狀態

- 五行之氣：木、火、土、金、水，各為 0–10 的整數，開局皆為 5。
- 狀態字樣：0–2「虛」、3–6「平」、7–9「盛」、10「亢」。
- 德：分數，開局 0。
- 順、逆：本季累計次數。
- 牌庫、手牌（上限 4）、棄牌堆。
- 徵兆與禍患清單。
- 亂數種子：存在狀態裡，讀檔後不會重新洗牌，測試可重現。

### 3.2 時間

一季六旬，以節氣命名。春：立春、雨水、驚蟄、春分、清明、穀雨。全年二十四旬。

### 3.3 一旬的流程

1. **晨報**：第 1–5 旬各翻開一張事件，以「徵兆」狀態進場。第 6 旬不出新事件。
2. **補牌**：手牌補到 4 張。牌庫用完時把棄牌堆洗回。
3. **施政**：每打一張牌花 1 枚「令」。令的數量看火氣：7 以上 3 枚、4–6 為 2 枚、1–3 為 1 枚。
4. **挑燈**（選用，每旬一次）：立刻多 1 枚令；結算時火 −1、水 −1，且本旬作息視為不合時。
5. **就寢**：三選一：夜臥早起、早臥早起、早臥晚起。合乎當季者火 +1。
   - 春、夏：夜臥早起。秋：早臥早起。冬：早臥晚起。
   - 天師在此時說「陛下，該睡了」。
6. **結算**：見 3.6。

### 3.4 行動牌

每張牌有：五行、時令標籤（生、長、收、藏）、效果。打出後進棄牌堆。

時令：春配「生」、夏配「長」、秋配「收」、冬配「藏」。對立為生↔收、長↔藏。

- 打出與當季相同標籤的牌：順 +1，當季五行 +1（每旬只加一次）。
- 打出與當季對立標籤的牌：逆 +1，當季五行 −1（每次都扣）。
- 其他標籤：無額外影響。

### 3.5 事件：徵兆與禍患

事件進場時是「徵兆」，只顯示一段描述（例如「將軍近日眼眶泛紅，說話又急又快」），不直接寫出效果。當旬沒化解，結算時轉為「禍患」，之後每旬結算扣該五行 1 點，直到化解。

化解方式：打出符合條件的牌。牌的效果照常發動，並化解最早進場且符合條件的一個事件。

- **情志類**：打出「剋它」的五行牌。木←金、火←水、土←木、金←火、水←土。
- **天候類**：打出同五行或「生它」的五行牌（木←水、火←木、土←火、金←土、水←金）。另外，徵兆轉禍患時若該五行的氣在 7 以上，自動消散，視同在徵兆階段化解。

得分：徵兆階段化解 +3 德，禍患階段化解 +1 德。這就是「治未病」，不向玩家說破。

### 3.6 結算順序（固定，引擎逐步輸出紀錄供畫面播放）

1. 作息：挑燈扣火 1、水 1；否則作息合時則火 +1。
2. 禍患各扣其五行 1。
3. 徵兆轉禍患（天候類先判定是否自動消散）。
4. 相生：以此刻的數值為準，氣在 8 以上的五行，讓它所生的五行 +1（木→火→土→金→水→木）。同時計算。
5. 亢害：以步驟 4 之後的數值為準，氣為 10 的五行，讓它所剋的五行 −1（木剋土、土剋水、水剋火、火剋金、金剋木），自己也 −1。
6. 數值限制在 0–10。
7. 判定告假與國危（3.7）。
8. 本旬至少打出一張當季標籤的牌，則德 +1。

### 3.7 失敗與過關

- 大臣的氣降到 0：告假。該五行的牌無法打出，直到氣回到 3 以上。
- 火降到 0，或同時兩位大臣告假：國危，遊戲結束。
- 撐過第 6 旬即過關，結算評等。

季末加分：五行全部落在 4–8 之間，德 +5（平衡）。

評等（門檻待模擬後調整）：德 18 以上「聖」、10–17「賢」、其餘「常」。

### 3.8 季與季的牽連（完整版，原型不做）

季末若當季五行的氣低於 5，或逆達 3 次，下一季開局多一張禍患：

| 逆的季節 | 下一季的禍患（表面名稱） | 原文 |
|---|---|---|
| 春 | 六月飛霜 | 夏為寒變 |
| 夏 | 寒熱不定 | 秋為痎瘧 |
| 秋 | 倉廩滲漏 | 冬為飧泄 |
| 冬 | 將士乏力 | 春為痿厥 |

## 5. 畫面

手機直向 390 像素寬為基準，桌機置中、最大寬度 480。由上到下：

1. 頂列：節氣名、第幾旬（n/6）、德。
2. 王國地圖：原型用 SVG 佔位，五個區塊依東、南、中、西、北排列，各顯示大臣名、氣的十格條、狀態字樣（虛、平、盛、亢）與數字。
3. 事件列：徵兆與禍患，以邊框樣式區分，點開看描述。
4. 令的數量、「挑燈」與「就寢」按鈕。
5. 手牌：四張橫排，顯示牌名、五行字、標籤、效果。

互動與動態：

- 點牌即打出；令不足或該五行告假時，牌顯示為不可用並說明原因。
- 數值變動時，在對應區塊浮出「+1」「−1」。
- 結算依 3.6 的步驟逐步播放，每步約 400 毫秒並顯示一行說明；點一下可略過。
- 遵守 `prefers-reduced-motion`。觸控目標至少 44 像素。五行不只靠顏色區分，一律同時顯示文字。

樣式沿用青石驛家族：

- 紙色 `#f6e8cf`、淺紙 `#fbf3e4`、墨 `#3a3631`、淡墨 `#6a6157`、線 `#e3d3b6`、青石 `#4e5e5f`、金 `#8f6b2c`。
- 五行（與四時相同）：木 `#2e6b3a`、火 `#ad3a2c`、土 `#85561a`、金 `#5a6270`、水 `#2b5a8a`。
- 標題字體 `"Noto Serif TC","Songti TC","PMingLiU",serif`；內文用系統黑體，寫法同青石驛。

頁尾比照四時：`.home-link`「回到青石驛」按鈕（含 `qingstone.png`）、GoatCounter 計數、版權聲明；`<head>` 加 `format-detection` 關閉電話連結、主畫面圖示。直接參考 `imqingstone/sishi` 的 `docs/index.html` 與 `docs/style.css`。

## 6. 程式架構

```
docs/            GitHub Pages 發布目錄（main 分支的 /docs）
  index.html
  style.css
  data.js        牌、事件、季節、文字、所有數值常數
  engine.js      規則引擎：純函式，不碰 DOM 與 localStorage
  app.js         畫面與存檔
tests/verify.js  node tests/verify.js
design/SPEC.md   本文件
```

- `engine.js` 與 `data.js` 同時能在瀏覽器與 Node 執行（檔尾以 `if (typeof module !== 'undefined') module.exports = …` 匯出）。
- 引擎介面：`newGame(seed)`、`playCard(state, handIndex)`、`burnLamp(state)`、`endTurn(state, rest)`、`canPlay(state, handIndex)`。一律不修改傳入的狀態，回傳 `{ state, log }`；`log` 是事件陣列（例如 `{ type: 'qi', element: '木', delta: 1, reason: '相生' }`），畫面只依 `log` 播放。
- 亂數用帶種子的 mulberry32，種子與游標存在狀態裡。
- 規則不得寫在 `app.js`。

存檔：

- `localStorage` 鍵名 `linglan.save.v1`，內容 `{ v: 1, state }`。每次行動後自動存。
- 讀寫都包在 try/catch；讀不到或版本不符時開新局，不可當掉。
- 提供匯出與匯入 JSON 檔（做法參考觀易的手記備份），匯入前驗證格式。

## 7. 測試

`tests/verify.js` 不依賴任何套件，失敗時以非零狀態碼結束。

1. 規則：3.4–3.7 每一條各有案例，包含結算順序。
2. 不變量：任意操作後氣在 0–10、手牌不超過 4、全部牌數守恆、不修改輸入狀態。
3. 重現性：同種子、同操作，結果完全相同。
4. 模擬：1000 個種子跑到結束不出錯。
5. 平衡護欄：隨機亂打的過關率低於 40%；「優先化解徵兆、其次打當季牌、作息合時」的簡單策略過關率在 70%–95%。不符時調整 `data.js` 的常數，並在提交訊息說明。
